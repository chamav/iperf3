# ТЗ: Android-приложение «iperf3 Client» (MVP)

## 1. Цель и результат
**Цель:** создать локально запускаемый клиент iperf3 для измерения пропускной способности сети (TCP/UDP) с удобным UI, историей тестов и экспортом, без рекламы на первом релизе, но с заложенными местами для её добавления позже.

**Результат MVP:**
- Сборка APK (arm64) для ручной установки и тестирования на **Samsung Galaxy Fold 6 (SM-F956B)**.
- Работоспособные режимы тестов iperf3 (TCP/UDP), конфигурация параметров, визуализация результатов, лог/история, экспорт CSV/JSON.
- Соответствие базовым требованиям приватности и фоновому выполнению, готовность к дальнейшей публикации в сторах.

## 2. Термины
- **Iperf**/**iperf3** — инструмент/протокол измерения сетевой производительности (клиентская часть в приложении).
- **Сессия теста** — один запуск измерения с набором параметров и полученными метриками.
- **FGS** — foreground service (служба переднего плана).

## 3. Платформа и устройства
- **Целевая платформа:** Android (ARM64).
- **Поддерживаемые ABI на старте:** `arm64-v8a` (обязательно).  
  *Опционально:* подготовить конфигурацию для добавления других ABI в будущем.
- **Минимальная версия Android:** не жестко задавать; обеспечить сборку на уровне, позволяющем запуск на Galaxy Fold 6.  
- **Target SDK:** «актуальный на момент сборки».  
- **Особенности foldable:**
  - Корректная работа при **смене состояния «сложен/разложен»**, поворотах и в режиме **мультиоконности**.
  - Адаптивные макеты (одно-/двухпанельный интерфейс при увеличенной ширине).

## 4. Объём работ (Scope)

### 4.1. Функциональные требования (MVP)
1. **Экран «Домой / Тест»**
   - Поля: хост (DNS/IP), порт, протокол (TCP/UDP), длительность, количество потоков, **reverse** (сервер->клиент), для UDP — целевой битрейт.
   - Тумблер: «Только по Wi-Fi» (блокировать запуск при мобильных данных, если включён).
   - Кнопки: **Старт**, **Стоп** (прерывание текущей сессии).
   - Индикация прогресса, текущей скорости/потерь/джиттера (по мере выполнения).

2. **Список серверов**
   - Локально сохраняемые записи: имя, адрес, порт, протокол по умолчанию, заметка.
   - Действия: добавить/редактировать/удалить/выбрать активный.

3. **Предустановки (Presets)**
   - Сохранение/загрузка набора параметров теста.

4. **Результаты и история**
   - Сохранение каждой сессии: параметры запуска + агрегированные метрики.
   - Просмотр детальной карточки результата: таблица метрик + графики (скорость/джиттер/потери/ретрансмиты).
   - Поиск/фильтры в истории (по хосту, дате, протоколу).
   - **Экспорт** выбранной сессии и/или диапазона в **CSV**/**JSON**.
   - **Шаринг** экспорта через стандартный системный диалог.

5. **Логи**
   - Читаемый лог сессии (сырой вывод iperf3/агрегированный), доступ к копированию/шарингу.
   - Ротация/ограничение размера логов.

6. **Настройки**
   - Глобальные ограничения (макс. длительность, макс. параллельных потоков).
   - Единицы отображения (Мбит/с и т.д.).
   - Тумблер «Разрешить фоновые тесты только как FGS».
   - Переключатель «Собирать анонимную диагностику» (**выкл** по умолчанию; интерфейс-заглушка без фактической отправки в MVP).

7. **О справке / лицензии**
   - Краткая справка, предупреждение о расходе трафика/нагрузке.
   - Атрибуция лицензии iperf3 (BSD) и список используемых OSS-компонентов.

8. **Onboarding (первый запуск)**
   - Короткий скрин об ответственности и расходе трафика.
   - Объяснение причин потенциальных запросов разрешений.

> **Не включаем в MVP:** рекламу, платёжные функции, удалённую телеметрию.

### 4.2. Нефункциональные требования
- **Производительность:** UI не должен «замерзать» во время теста; обновления прогресса не реже 2–4 раз/сек.
- **Надёжность:** корректное прерывание сессии, предсказуемые таймауты сетевых операций.
- **Энергопотребление:** отсутствие «вечных» фоновых циклов; тесты только по действию пользователя.
- **Безопасность/приватность:** не собирать персональные данные; не отправлять ничего наружу в MVP.
- **Локализация:** RU/EN минимум.
- **Доступность:** поддержка масштабирования шрифтов, контраст, доступность элементов управления.

## 5. Права и политики
- **Разрешения (динамически по необходимости):**
  - Базовые: `INTERNET`, `ACCESS_NETWORK_STATE`.
  - Для показа SSID/характеристик Wi-Fi (если требуется): разрешения на доступ к близлежащим Wi-Fi/геоданным, в зависимости от версии Android.
  - Для отображения уведомления FGS: запрос на показ уведомлений на современных версиях Android.
- **Фоновая работа:** длительный тест выполняется в FGS с постоянным уведомлением; автозапусков нет.
- **Сетевое поведение:** отсутствие скрытых периодических тестов; запуск — только руками пользователя.
- **IPv6/NAT64:** приложение должно уметь работать с IPv4 и IPv6, корректно разрешать DNS-имена.

## 6. Архитектура (без привязки к стеку)

### 6.1. Слои
- **UI слой:** экраны, управление состоянием, навигация, доступность, адаптация под foldable/large screen.
- **Доменный слой:** сценарии (use cases) — подготовка параметров, запуск, остановка, парсинг и агрегация результатов, сохранение в репозиторий.
- **Инфраструктура:**
  - **IperfEngine** — абстракция над iperf3 (см. интерфейс ниже).
  - **Storage** — локальное хранилище (БД/файлы) для серверов/истории/логов.
  - **Export/Import** — формирование CSV/JSON и их шаринг.
  - **FGS/Notifications** — управление жизненным циклом фонового теста.
  - **AnalyticsHost (заглушка)** — интерфейс для будущей диагностики.
  - **AdsHost (заглушка)** — интерфейс под будущие рекламные размещения.

### 6.2. Контракты (псевдо-интерфейсы)

**IperfEngine**
```
interface IperfEngine {
  // Синхронный или асинхронный запуск клиентского теста
  startClient(params: TestParams, listener: ProgressListener): SessionId
  // Прерывание активной сессии
  stop(sessionId: SessionId): void
  // События прогресса/логов/завершения (через listener/коллбек/шину событий)
}

data TestParams {
  host: string
  port: int
  protocol: enum { TCP, UDP }
  durationSec: int
  parallelStreams: int
  reverse: bool
  udpBitrateMbps?: float
  // Доп.параметры: window size, MSS, bind local iface, tos и т.п. — как расширения
}

data LiveMetricsTick {
  second: int
  throughputMbps: float
  jitterMs?: float       // UDP
  packetLossPct?: float  // UDP
  retransmits?: int      // TCP
  rttMs?: float          // опционально
  rawLine?: string       // сырой лог при необходимости
}

data TestResult {
  startedAt: timestamp
  finishedAt: timestamp
  params: TestParams
  summary: {
    avgMbps: float
    maxMbps: float
    minMbps: float
    jitterMs?: float
    packetLossPct?: float
    retransmits?: int
    rttMs?: float
  }
  timeline: List<LiveMetricsTick>
  rawLogPath?: string
}
```

**Storage**
```
interface ServersRepository {
  list(): List<ServerItem>
  add(item: ServerItem): Id
  update(item: ServerItem): void
  delete(id: Id): void
  get(id: Id): ServerItem?
}

interface HistoryRepository {
  insert(result: TestResult): Id
  get(id: Id): TestResult?
  query(filter: HistoryFilter): Paginated<TestResult>
  delete(id: Id): void
  purge(olderThan: timestamp): int
}
```

**Export/Import**
```
interface Exporter {
  toCSV(resultIds: List<Id>): FileRef
  toJSON(resultIds: List<Id>): FileRef
}
```

**AdsHost (заглушка)**
```
interface AdsHost {
  initIfAllowed(): void
  // Места размещений (см. UI ниже) — методы пока пустые
  showBanner(slotId: string): void
  showInterstitial(slotId: string, onFinished): void
}
```

## 7. UI/UX и экраны

### 7.1. Экран «Домой/Тест»
- Поля параметров (см. 4.1.1).
- Кнопка **Старт** (активна при валидных полях).
- Индикатор состояния (ожидание/выполняется/завершено/ошибка).
- **Прогресс-панель** с текущими метриками и мини-графиком.
- **Место под баннер** (нижняя часть, заглушка не отображает рекламу в MVP).

### 7.2. «Серверы»
- Список с быстрым выбором, кнопка «+».
- Форма добавления/редактирования.
- Пометка «по умолчанию».

### 7.3. «История»
- Список прошлых сессий (дата, хост, протокол, средняя скорость).
- Поиск/фильтры.
- Мультивыбор для экспорта/удаления.

### 7.4. «Детали результата»
- Блок «Параметры запуска».
- Графики: скорость по времени; для UDP — джиттер/потери; для TCP — ретрансмиты/RTT (если доступны).
- Кнопки: **Экспорт CSV/JSON**, **Поделиться**, **Открыть лог**.

### 7.5. «Настройки»
- Лимиты (длительность, потоки).
- «Только Wi-Fi».
- «Собирать диагностику» (выкл, описание).
- Управление хранением (очистка кэша/логов/старых результатов).

### 7.6. «О программе / Лицензии / Политика»
- Текстовое предупреждение о расходе трафика.
- Лицензия iperf3 (BSD).
- Ссылка на политику конфиденциальности (локальный экран/URL-заглушка в MVP).

### 7.7. Foldable/large-screen
- На широких экранах: **двухпанельный режим** (слева список/параметры, справа прогресс/результат).
- Сохранение состояния при сворачивании/разворачивании устройства.

## 8. Обработка ошибок и крайних случаев
- Некорректный хост/порт, таймаут подключения.
- Блокировка UDP оператором/файрволом.
- Потеря сети во время теста (пауза недоступна — предложение прервать и сохранить частичный результат).
- Превышение лимитов (длительность/потоки) — валидация на UI.
- Недостаточно прав (например, доступ к Wi-Fi информации) — объясняющий диалог + ссылка на Настройки.

## 9. Хранение данных
- Локально, без внешней синхронизации.
- **Схемы:**
  - `servers` (id, name, host, port, defaultProtocol, note, createdAt, updatedAt).
  - `results` (id, startedAt, finishedAt, params(JSON), summary(JSON), timeline(отдельная таблица или JSON-файл), rawLogPath).
- **Ротация/Retention:** настройка в «Настройках» (например, хранить не более N записей или не старше X дней).
- Резервные копии/восстановление — на усмотрение ОС (не требовать собственную реализацию в MVP).

## 10. Экспорт/импорт
- **CSV:** табличная выгрузка агрегатов и, опционально, покадровых метрик.
- **JSON:** полный объект `TestResult` с таймлайном.
- **Шаринг:** системный диалог (email/мессенджеры/файлы).
- **Импорт:** не обязателен в MVP (заложить интерфейс для будущего чтения JSON).

## 11. Логи и диагностика
- Локальный лог выполнения сессии (ограничение размера/ротация).
- Отдельный лог приложения (уровни: error/warn/info/debug).
- Кнопка «Поделиться логами» на экране «О программе».

## 12. Заготовки под рекламу и аналитику (не активны в MVP)
- В коде: интерфейсы **AdsHost** и **AnalyticsHost**, точки и **slotId**:
  - Баннер на экране «Домой/Тест» (низ).
  - Интерстициал по завершении теста (после экрана результатов) — **заглушка**, вызовы не производить.
- В «Настройках»: переключатель «Персонализированная реклама» (**выкл**, не задействован).
- В «Политике»: абзац о том, что реклама может быть добавлена в будущих версиях.

## 13. Безопасность и приватность
- Приложение **не** собирает, **не** отправляет и **не** хранит персональные данные в облаке.
- Вся история/логи — **только локально** на устройстве, с возможностью удаления.
- На экране «О программе» — понятное объяснение сетевой нагрузки и ответственности пользователя.

## 14. Тестирование и приёмка

### 14.1. Тест-матрица
- Устройства: **Samsung Galaxy Fold 6** (сложен/разложен), минимум ещё один обычный смартфон (для проверки без foldable).
- Сети: Wi-Fi (2.4/5/6 ГГц, если доступно), мобильная сеть (запрет запуска при включённом «Только Wi-Fi»), IPv4/IPv6 (если доступно).
- Продолжительные тесты: 10–15 мин (ручная проверка энергопотребления и стабильности).

### 14.2. Юнит/интеграционные тесты
- Парсинг вывода iperf3 в `LiveMetricsTick` и `TestResult`.
- Валидация параметров (границы, обязательность).
- Сохранение/загрузка из хранилища, экспорт CSV/JSON.

### 14.3. Инструментальные/ручные сценарии
- Запуск TCP-теста к известному серверу (LAN/интернет), получение осмысленных значений.
- Запуск UDP-теста с заданным битрейтом (обработка потерь/джиттера).
- Прерывание теста → результат сохраняется как «прервано», логи доступны.
- Повороты экрана, сворачивание/разворачивание Fold — состояние не теряется.
- Экспорт результатов и шаринг файла.
- Проверка уведомления FGS и права на уведомления (современные версии Android).

### 14.4. Критерии приёмки
- Успешный прогон всех сценариев без крашей.
- Стабильная работа на Galaxy Fold 6, отсутствие заморозок UI во время теста.
- Корректность сохранения истории и экспорта.
- Соответствие разделам 4–13.

## 15. Сборка и артефакты
- **Артефакты для заказчика:**
  - `app-arm64-debug.apk` (или `app-universal-debug.apk`) — для ручной установки.
  - Исходники, инструкция `README.md` по сборке и ручной установке APK.
  - Версионирование: `versionName` `0.1.0`, `versionCode` — целое, инкрементировать на каждый билд.
  - Конфигурация shrink/obfuscation с сохранением читаемости логов (mapping файл, если включена обфускация).

## 16. Будущие расширения (вне MVP)
- Встраивание рекламы (баннер/интерстициал) через `AdsHost`.
- Аналитика запуска/ошибок через `AnalyticsHost` с явным согласием.
- Импорт результатов из файлов JSON.
- Поиск локальных iperf-серверов в LAN (mDNS/Bonjour) — отдельным разрешением и UX.
- Виджет/быстрый запуск теста, ярлыки, плитки.
- Профили «Стресс-тест», «Щадящий», «Короткий».

## 17. Риски и меры
- **Публичные iperf-серверы** нестабильны → по умолчанию пустой список, пользователь добавляет свои (или ваши контролируемые).
- **Энергопотребление** при длинных тестах → предупреждения, лимиты в настройках.
- **Разрешения** меняются между версиями Android → защищённые проверки, объясняющие диалоги.
- **IPv6/NAT64** → обязательное тестирование и запрет на жёстко прошитые IPv4-адреса в примерах.

## 18. Лицензии
- Включить текст BSD-лицензии iperf3 на экране «О программе» и в файл `LICENSES.txt` внутри APK.

### Примечания для сборки APK под тест на Galaxy Fold 6
- Собрать **arm64 APK** (debug) и проверить на реальном устройстве:
  - Сценарии из раздела 14.3.
  - Folded/Unfolded, split-screen.
  - Wi-Fi-тесты (включая «Только Wi-Fi»).
- В `README.md` приложить инструкцию по установке APK и перечень известных ограничений (если появятся) к первой проверке.
